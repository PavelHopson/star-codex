Локальный HTTP/SSE-шлюз Responses API и изолированный запуск Codex CLI. Профили явно задают модель; число запросов, параллельность и размер данных ограничиваются настройками.

Самостоятельная реализация, вдохновлённая управлением провайдерами в Claudish. Исходники, промпты и конфигурация Claude не копируются. Инструмент не содержит npm-зависимостей и не меняет глобальные настройки Codex.

## Требования

Node.js 22+ и отдельно установленный Codex CLI. В исходной документации проверка описана для Node.js 24 на Windows. Для реальной задачи нужен совместимый локальный сервер Responses API.

## Возможности и ограничения

- Передача Responses API по HTTP/SSE, включая function/custom tools и пространства имён Codex.
- Upstream разрешён только на буквальном `127.0.0.1`. Для StarAI требуется отдельно настроенный SSH-туннель; инструмент не создаёт его и не меняет сервер.
- Ограничения запросов на сессию и параллельности на процесс. Очередь, автоматические повторы и резервный провайдер отсутствуют. Тайм-аут охватывает загрузку тела и весь поток ответа.
- Ограничения входных и выходных байтов и запрошенных токенов. Лимит токенов передаётся провайдеру и не является гарантированным ограничением GPU, RAM или стоимости.
- Временный bearer-токен, запрет доступа из браузера, отсутствие передачи upstream-аутентификации, cookies и текстов ошибок. Внешние медиа-URL и hosted tools не поддерживаются; неизвестные маршруты отклоняются.
- Изолированный Codex home в `.runtime`, sandbox только для чтения, политика подтверждений `on-request`. Этот запуск не предоставляет инструменты изменения или развёртывания. Он не защищает от злоумышленника с доступом к ОС или скомпрометированного Codex.
- Журнал содержит счётчики, статусы и длительность без токенов, промптов и ответов. `cost: null` означает «не измерено». Завершение транспорта не доказывает корректность модели или выполнение инструмента.

Файлы самого Codex могут содержать пользовательский контент. Каталог `.runtime` должен оставаться приватным.

## Проверка в Windows PowerShell

Из корня клонированного репозитория:

```powershell
node .\src\cli.mjs check
node .\src\cli.mjs demo
node --test test/*.test.mjs
```

`check` проверяет конфигурацию. `demo` использует синтетический локальный сервер, а не AI-модель. Эти команды не обращаются к реальной модели и не меняют репозиторий.

## Запуск задачи с моделью

Сначала подтвердите совместимость endpoint с Responses, streaming и function tools и настройте профиль. Пример имени `local-code` исторический: наличие такой модели не подтверждено. Endpoint только с Chat Completions автоматически не преобразуется.

Из корня репозитория:

```powershell
$codexBinary = (Get-Command codex.exe -ErrorAction Stop).Source
$workspacePath = (Get-Location).Path
'Опиши этот репозиторий. Не изменяй файлы.' | node .\src\cli.mjs run --profile local-code --workspace $workspacePath --codex $codexBinary
```

Нужен нативный `codex.exe`, а не shell shim. При ошибке запуск останавливается; не повторяйте реальный запрос без выяснения причины.

Vision по умолчанию отключён. При явном включении принимаются только встроенные данные PNG/JPEG/WebP.

## Границы интеграции

Экземпляры wrapper имеют независимые лимиты и не распределяют общий GPU-бюджет. На Ctrl+C launcher закрывает шлюз и завершает собственный прямой дочерний процесс Codex; это не изоляция дерева процессов на уровне ОС.

Инструкции открытого проекта остаются входными данными для Codex. Непроверенный проект нужно изучить до запуска. Loopback-адрес также не доказывает, что сам сервер модели не использует облако; системная изоляция сети не заявляется.

До рабочего подключения StarAI нужно проверить протокол и возможности установленной модели, текстовый ответ, вызов и результат инструмента, отмену, сжатие контекста и отказ провайдера. Облачная маршрутизация, учёт денежных бюджетов, адаптер Chat Completions, конвертация изображений, общая очередь GPU и UI в версии 0.1 не реализованы.
